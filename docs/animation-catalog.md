# Animation catalog

The register of every clip this project has: what ships in the character GLB, how
each one was produced, what it's bound to, and what's still sitting unused in the
source library. Companion to:

- [baking-animations.md](./baking-animations.md) — *how* the bake works.
- [matrix-online-combat-animation-roadmap.md](./matrix-online-combat-animation-roadmap.md)
  — *what moves* the game eventually wants.

This file is the shopping list between the two: before authoring a new move, check
here for a clip that already exists.

## Regenerating the tables

```bash
npm run clips                                             # the shipped asset
node scripts/list-clips.mjs models-src/UAL2_Standard.glb  # the source library
```

[`scripts/list-clips.mjs`](../scripts/list-clips.mjs) reads the GLB's JSON chunk
directly, so it works on the Draco-compressed shipped file too. Re-run it after a
bake and update the tables below if the clip set changed.

## Authoring tiers

Every shipped clip records **how custom it is**, so the cost of each one is visible
and reviewable:

| Tier | Meaning |
|---|---|
| **P** — pass-through | Library clip embedded as-is; the bake only selects, renames, or resamples it. |
| **T** — tweaked | Library motion kept, but retimed, mirrored, trimmed, or partially overridden (e.g. lower body kept, upper body replaced). |
| **A** — authored | Motion generated by a recipe in `scripts/lib/`; the library clip is a phase/timing reference at most. |

The tier is a **per-clip decision, not a project-wide setting**. Start at P; move up
only when the library clip is actually wrong for the game — that judgement, and its
reason, is what the Notes column is for. `Walk`/`Run` are A because UAL2 ships
neither; `Melee_Hook` is P because a hook punch is a hook punch.

## Authored recipes

`Walk` and `Run` are built by [`scripts/lib/locomotion.mjs`](../scripts/lib/locomotion.mjs),
called from the bake. Tune the feel via the `WALK` / `RUN` constant blocks at the
top of that module, re-bake, then verify:

```bash
node scripts/inspect-locomotion.mjs models-src/agent-animated.glb Walk Run
```

Arm/leg correlation should sit near **−1.00** (each arm opposing the leg on its own
side). Two ordering rules bite if the recipe is rearranged — `setHipPitch` before
`authorArms`, and the run's leg exaggeration about the clip's own mean pose — both
explained in [baking-animations.md](./baking-animations.md#walk-and-run-are-authored-not-copied).

## Gotchas when adding a clip

1. **Substring matching.** `CLIP_NAMES` fragments match case-insensitively as a
   substring, in list order — `['walk']` would happily bind `Zombie_Walk_Fwd_Loop`
   if that clip were ever baked in. Use a fragment specific enough to be safe, or
   rename the clip during the bake.
2. **Name parity with Decentraland.** DCL's `Animator` matches the **exact** clip
   name; our loader matches loosely. Keep state name ↔ clip name aligned so one
   name satisfies both engines.
3. **`speedFactor` is per-state** — ground speed over the speed *that state's* clip
   was authored for. A new locomotion state needs its own reference speed in
   `Player.update`, or it gets driven at the walk's rate.
4. **It must be in `KEEP`.** Wiring a clip in `AnimationController` does nothing if
   the clip isn't in the shipped GLB: add its exact name to the `KEEP` set in
   [`scripts/bake-animations.mjs`](../scripts/bake-animations.mjs) and run
   `npm run bake:anims:dcl`.
5. **Never hand-edit `public/models/agent-dcl.glb`** — it is a build artifact.

## Adding a custom (tier A) clip

1. Write the recipe as a module in `scripts/lib/`, alongside
   [`locomotion.mjs`](../scripts/lib/locomotion.mjs) — it gets the gltf-transform
   document and the skeleton helper, and calls
   `writeClip(doc, name, pose, skel, timeScale)`.
2. Call it from `scripts/bake-animations.mjs` after the merge/rebind step, and add
   the new name to `SYNTHESIZED` so the clip-count check stays honest.
3. Verify with `node scripts/inspect-locomotion.mjs models-src/agent-animated.glb <Clip>`.
4. Bind it in `AnimationController` and record it in the shipped table above.

For a move with no library source and no procedural shortcut — most kicks — the
cheaper path is to author it in Blender/Cascadeur on this same rig, export it as
another `.glb` clip library into `models-src/`, and point the bake at that. The
bake accepts any same-rig library, so a hand-authored pack drops straight in.
